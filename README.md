# StudyStack V2 改修ミッション

StudyStack V1を完成版として凍結し、V2では

「既存システムに追加要件が発生した」

という想定で、保守・改修を行う。

## 必須要件

- Study投稿時に、あらかじめ定義されたタグを選択できる
- タグによるStudyの絞り込みができる
- 週間目標を設定できる

## 拡張要件

- 週間目標を約7週間分表示し、期限管理を行う
- 期限数日前の通知機能

## 改修方針

追加要件確認  
→ 既存コードの影響範囲調査  
→ 改修方針決定  
→ 小さく実装  
→ 追加テスト  
→ 既存テストによる回帰確認

一度に大きく変更するのではなく、小さな単位で実装と確認を繰り返し、既存機能への影響を確認しながら改修を進める。


# タグ機能 要件

## 基本仕様

- タグは運営側があらかじめ定義する
- 一般ユーザーによるタグの追加・編集・削除は行わない
- 1つのStudyに設定できるタグは最大2個
- タグを設定しないStudyも登録可能
- 同一Studyに同じタグを重複して設定することはできない
- 同一名のタグは複数作成できない
- StudyとTagは多対多（Many-to-Many）の関係とする

## 新規登録

- Study投稿時に定義済みタグから選択できる
- 最大2個まで選択可能
- タグを選択せずにStudyを登録することも可能
- 3個以上選択した場合はForm側でバリデーションエラーとする
- JavaScript側でも3個以上の選択を防止する

## 更新

- Studyに設定済みのタグを選択状態で表示する
- タグの変更・追加・解除ができる
- 更新後も0〜2個の制約を維持する
- 3個以上選択した場合は更新せず、既存データを維持する
- 同じタグの重複設定は許可しない

## 一覧表示

- DashboardのStudy一覧に設定済みタグを表示する
- タグはチップ形式で表示する

## タグ絞り込み

- Dashboardに定義済みタグのフィルターを表示する
- 選択したタグを利用してStudy一覧を絞り込める
- 「すべて」を選択すると絞り込みを解除できる

## UI

- 複数選択可能なタグ選択UIを使用する
- JavaScriptで選択中のタグをチップ形式で表示する
- 選択状態が変化するたびにチップ表示を更新する
- 3個目のタグが選択された場合、直前の正常な選択状態へ戻す
- 最大2件という制約はForm側でも検証し、JavaScriptだけに依存しない
- チップから直接タグを解除する機能はV2では実装対象外とする


# タグ機能 影響範囲調査

## models.py

影響あり。

V1のStudyモデルは以下の情報を保持していた。

- user
- content
- created_at

タグ情報を保持する仕組みが存在しなかったため、新しくTagモデルを追加し、Studyとの関連を定義した。

1つのStudyに複数のTagを設定でき、同じTagを複数のStudyで利用するため、StudyとTagは多対多の関係となる。

そのため、Studyモデルに `ManyToManyField` を追加した。

また、同一名のタグが複数作成されることを防ぐため、Tagの `name` には `unique=True` を設定した。


## forms.py

影響あり。

V1のStudyFormはcontentのみを入力項目として扱っていたため、タグを選択できるようフォームを拡張した。

タグは未選択を許可し、以下の条件でバリデーションを行う。

- タグ0個：許可
- タグ1個：許可
- タグ2個：許可
- タグ3個以上：不許可

タグ最大2件の制約は `StudyForm` のバリデーションで行う。

JavaScriptによる選択数制御も追加したが、JavaScriptが無効な場合や直接POSTされた場合でも制約を維持できるよう、Form側のバリデーションを正式な制約としている。


## views.py

影響あり。

新規登録では以下の流れでStudyを保存する。

- StudyFormを生成
- `form.is_valid()` で検証
- `form.save(commit=False)` でStudyを生成
- ログインユーザーを設定
- Study本体を保存
- `form.save_m2m()` でTagとの多対多の関連を保存

ManyToManyの関連はStudy本体の保存とは別に保存する必要があるため、`form.save_m2m()` を追加した。

Updateでは既存Studyを `instance` としてStudyFormへ渡し、現在のタグを保持した状態から変更・追加・解除を行う。

また、Dashboardでは指定されたタグをもとにStudy一覧を絞り込む処理を追加した。


## templates

影響あり。

### dashboard.html

以下を追加・変更した。

- タグ選択UI
- 選択中タグのチップ表示領域
- Study一覧への設定済みタグ表示
- タグバリデーションエラー表示
- タグ絞り込みUI

タグ一覧はStudyごとに `study.tags.all` を利用して表示する。

### update.html

以下を追加・変更した。

- 現在設定されているタグの選択状態表示
- タグの追加
- タグの変更
- タグの解除
- 選択中タグのチップ表示領域
- タグバリデーションエラー表示


## JavaScript

タグ選択UIの操作性を改善するため、JavaScriptを追加した。

主な処理は以下。

- `change` イベントによるタグ選択状態の検知
- `selectedOptions` から現在選択されているタグを取得
- 選択されたタグのチップを動的に生成
- 選択状態変更時にチップ表示を再描画
- 正常な選択状態を一時的に保持
- 3個目が選択された場合、直前の0〜2個の選択状態へ戻す

JavaScriptによる制御はユーザー操作を補助するためのものであり、データの整合性を保証するバリデーションは `StudyForm` 側でも行う。


## tests.py

影響あり。

V1で作成した既存テストを維持したまま、タグ機能に対するテストを追加した。

最終的に31件のテストを実行し、すべてGREENであることを確認した。

主な確認項目は以下。

### Form

- タグ0個でバリデーションを通過する
- タグ2個でバリデーションを通過する
- タグ3個でバリデーションエラーになる

### Model

- Studyに複数のTagを関連付けできる
- 同じTagを同じStudyへ複数回追加しても関連が重複しない
- 同じ名前のTagを複数作成できない

### View

- Dashboardからタグ付きStudyを作成できる
- Dashboardに設定済みタグが表示される
- Studyのタグを更新できる
- タグの追加・解除が正しく反映される
- 3タグで新規登録した場合、Studyが作成されない
- 3タグで更新した場合、既存Studyが変更されない
- バリデーションエラーが画面に表示される
- 指定したタグでStudy一覧を絞り込める
- タグ絞り込み後も他ユーザーのStudyが表示されない

既存テストを含めた全31件を実行し、タグ機能追加後も既存機能が壊れていないことを回帰確認した。

# 実装中に確認した仕様・設計上の注意点

## タグ最大2件の制約について

タグ最大2件の制約は `StudyForm` で実装している。

そのため、DashboardやUpdate画面などStudyFormを経由したユーザー操作では3件以上のタグを設定できない。

さらにUI上ではJavaScriptによる選択数制御を追加し、3個目のタグが選択された場合は直前の正常な選択状態へ戻すようにした。

一方で、Django Shellなどから直接、

```python
study.tags.add(tag)
```

を実行した場合はStudyFormを経由しないため、3件以上のTagをStudyへ関連付けることが可能であることを確認した。

例：

- Python
- Django

が設定済みのStudyに対して、ShellからAWSを直接追加すると、

- Python
- Django
- AWS

の3件を関連付けることができる。

V2では一般ユーザーによる操作をStudyForm経由に限定するため、タグ件数の制約はForm層で管理する方針とする。

Model・DB層まで含めて「どの経路からでも必ず最大2件」とする厳密な制約については、V2では実装対象外とする。


## 同一Tagとの関連について

同じTagを同じStudyへ複数回 `add()` した場合でも、StudyとTagの関連は重複して作成されないことをShellおよびModelテストで確認した。

例：

StudyとPythonがすでに関連付いている状態で、

```python
study.tags.add(python_tag)
```

を再度実行しても、Pythonとの関連は1件のままとなる。


## 同名タグについて

Tagの `name` に `unique=True` を設定し、完全一致する同名タグを複数作成できないようにした。

例：

- `Python`
- `Python`

は重複登録不可。

ただし、

- `Python`
- `python`
- `PyThOn`

など、大文字・小文字や表記揺れを同一タグとして扱うかどうかについてはV2では扱わない。

この問題は、ユーザー自身がタグを作成できる次回作の技術ブログで、タグ名の正規化を含めて要件から検討する。


## Update画面のタグチップ初期表示について

Update画面では、既存Studyに設定済みのタグはDjangoのフォーム上で選択済みとして表示される。

JavaScriptによるチップ表示はタグの選択状態が変更された際に反映する実装としているため、画面初期表示時に既存タグを自動でチップ化する処理はV2では実装しない。

初期描画処理の共通化やJavaScriptの責務分離については、次回作の技術ブログで改めて検討する。
